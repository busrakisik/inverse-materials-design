## Research goal and target domain

Can the 2024 *generalized cylindrical shells* (GCS) self-driving laboratory campaign provide scientifically honest evaluation data for an end-to-end Bayesian hypothesis/evidence acquisition system? **It is a separate domain** from the 2020 600×3 crossed-barrel historical V11 study; neither source may be silently substituted for the other.

Published scientific reference: Snapp et al., *Nature Communications* 15 (2024) 4290, DOI `10.1038/s41467-024-48534-4`. The paper reports **25,387 real experiments, 13,250 valid** across seven polymer families and an **11-parameter** design space. The campaign included deliberate human interventions, changing the experiment choice rules, geometry design space, and loaded materials. These are published overall figures, NOT counts rederived from a downloaded source CSV. An ID index is NOT an authenticated physical decision timestamp, especially with multiple printers and asynchronous testing.

Original author/BU institutional archive `https://open.bu.edu/items/871d47cb-a12c-4ebb-8623-92df97353ea9` (handle `2144/46687`), currently indexed file labels `CampaignData.csv` (about 7.54 MB), `FilamentData.csv` (about 13.36 KB), and multiple large `ADTS#.csv` Instron ZIP archives, e.g. `ADTS1-4999.zip` (about 680.37 MB). **No CSV header, bytes, actual original records, file digests, or per-run trace content were downloaded/verified at protocol freeze.** The archive description elsewhere calls the main metadata `Dataset.csv`, so publication prose and actual inventory file names must be reconciled from actual source bytes, not silently presumed synonymous. Source description states not every experiment had an Instron test, `Valid` identifies successfully included results, and some exclusions were due to physical/quality-control conditions. Exclusion is an observed outcome, not a prospective ground-truth candidate filter.

## Two separate gates: metadata vs honest counterfactual decision evaluation

- `SOURCE_METADATA_FEASIBILITY`: it may eventually be possible to analyze independently authenticated metadata, timestamps, 11 selected design inputs, experimental response outcomes, raw trace identity and missingness. Until actual file bytes and original mappings are examined, `metadata_bytes_verified=false`, `original_csv_header_verified=false`.
- `PREDICTION_TEST_FEASIBILITY`: one can potentially test prospective prediction using ONLY already measured historic responses with an independently frozen *chronological and grouped* holdout, correct distribution shifts and access parity. This is NOT an acquisition or hypothesis discovery win and will not be run in V12.20. It requires disjoint data and no invalid earlier peeking.
- `COUNTERFACTUAL_ACQUISITION_FEASIBILITY`: the logged historical campaign gives outcomes **for selected physical designs only**. A new BHS/GP/RF policy would usually choose DIFFERENT designs; their prospective physical responses were NOT measured. An offline simulator or GP surrogate invented from the same historical labels cannot make those missing counterfactual responses into independent real experimental evidence. Genuine off-policy decision/regret comparison needs a scientifically valid identification strategy (known logging propensities, sufficient action overlap, suitable support, appropriate doubly-robust/reweighting assumptions) or a new independently executed/prospectively randomized lab policy. The historical campaign is strongly adaptive with changing feasible candidate domains and human interventions, so even formal importance weighting might be impossible. **NO counterfactual discovery-performance score even after a CSV is downloaded unless these conditions are independently satisfied.**
- `PHYSICAL_MECHANISM_IDENTIFIABILITY`: per-experiment force–displacement curves could provide physically richer observables than toughness alone, BUT before claiming mechanism identification the exact source curve and sample ID must be verified, actual units and stopping/truncation respected, and physically distinct model predictions must be externally justified. Labels derived after test may be observed evidence, never prospective candidate features.

## Decision-stage feature passport (candidate, not source-field authorization)

The policy chooses an experiment at **stage 0**. Later milestones are useful for separate decisions but cannot be projected back to stage 0.

- Stage 0 `CANDIDATE_DESIGN`: 11 geometric design *recipe targets* and eligible/loaded material/active printer **if independently proven from predecision snapshot**; current study supports that these variables are *conceptually chosen before printing*, not the archived per-step access log. Model inputs from the GCS design library are candidate names only. `DecisionPolicy` code field can be logged as historical policy metadata, **not a predictive physical feature**.
- Stage 1 `PRINTED_AND_WEIGHED`: actual printed mass and as-built attributes are acquired after committing printing expense, so **not admissible before that experiment's initial selection**. Nominal target mass is a separate preprint design.
- Stage 2 `INSTRON_TESTED`: force–displacement trace, toughness, energy absorption and maximum stress are **after expensive mechanical testing**. No access until the selected run completes. Intrinsic strain/height readings derived from the Instron curve are also stage 2, not stage 0.
- Stage 3 `QUALITY_REVIEWED`: `Valid`, exclusion reasons and QC flags observed after testing/quality review; **post-selection missingness** potentially not at random. Treat invalid/non-tested runs as actions with physical cost and observed status; never delete these histories or report only the valid 13,250 as if all choices succeed.
- Stage 4 `AFTER_CAMPAIGN_PUBLICATION`: aggregate best-of-campaign, full-dataset hindsight, post hoc selection of best features/hyperparameters and results for all candidates. **Never usable at a historical decision time.**

Category `material_calibration` may precede some later runs but requires an independently timestamped material/filament calibration record and measurement chronology; it is NOT automatically available at stage 0 for the entire campaign. Historical hyperparameters fit from source outcomes are likewise only allowed after the corresponding **prior** observations, never leaked from a full dataset into an earlier policy.

## Frozen no-score software contract

Build an executable **metadata-only stage gate** with a closed enum for the five stages above. Each variable receives exactly one documented earliest feasible stage and a source/type classification, plus explicit flags for **actual archival field mapping verified** and **action-time log verified** (both FALSE for all current candidate features). Validate a synthetic-stage API in which measured outcomes and `Valid` cannot be passed as stage-0 fields; material calibration cannot be presented to decisions without a separately verified prior calibration event. Reject extra fields rather than dropping them silently. Reject any claim that numeric experiment ID by itself certifies chronological order. Source statuses must distinguish `PUBLISHED_SOURCE_DESCRIBES`, `AUTHENTICATED_RAW_FILE` and `ACTION_TIME_ACCESS_VERIFIED`.

Adversarial tests: stage 0 cannot see actual mass, Instron targets, `Valid`, source outcome-derived feature normalization, globally refitted hyperparameters or future material calibrations. At stage 2, Instron outcomes are available only for an explicitly marked FINISHED/REVEALED action, never a not-yet-selected candidate. At stage 3, failed or missing tests remain visible as statuses/costs, not silently omitted. Expected history can be reconstructed from synthetic records only; NEVER claim reconstructed chronology from final CSV order.

This phase uses NO external measured source rows, numerical energies, actual force/displacement values or BHS/GP/RF scored benchmark. Local or GitHub CI success proves software gating only.
